## DNP3 end-to-end template: existing implementation, not guarantees

### 1. Enablement, capture, dispatch, decode

- Config carries master `dpiEnabled`, mode, per-protocol toggle map, exclusions, kernel enforcement, NFLOG and NFQUEUE groups (C:pkg/cp/config/config.go:459-492). Engine builds filtered DPI manager and loads signature builtins (C:pkg/dp/engine/engine.go:154-176).
- Registration: `dnp3.NewDecoder()` and type-map `"dnp3"`; toggle filtering defaults unspecified protocols on (C:pkg/dp/engine/decoders.go:25,57,67-89). Enabling an `iec104` map key today would create no decoder.
- DNP3 `Supports` requires TCP and either port 20000; `Ports` advertises TCP/20000 (C:pkg/dp/ics/dnp3/decoder.go:22-35). No arbitrary-port payload classification.
- Selective DPI: inspect-all or IDS, otherwise ICS predicates whose transport/port matches; DNP3 default 20000 (C:pkg/dp/engine/engine.go:376-452). Payload events are recorded before enforcement (same file:498-505).
- Parsing: start bytes 05 64, minimum length/header CRC, station addresses, CRC-stripped payload and application FC (C:pkg/dp/ics/dnp3/frame.go:306-377). Data-block CRCs are skipped and truncated payloads partially accepted (same file:307,351-355). No DNP3 transport/application fragment state or select-before-operate transaction state in the stateless decoder (C:pkg/dp/ics/dnp3/decoder.go:17-20,38-45).
- Event fields: `function_code` (uint8), `function_name`, `is_write`, `is_control`, source/destination station addresses; optional IIN flags, comma-separated `object_groups`, first-header `qualifier`/`object_count`, capped `raw_hex`; Proto dnp3, Kind request/response/restart/control (C:pkg/dp/ics/dnp3/decoder.go:47-115).
- FC write/control sets include select 3, operate 4, direct operate 5/no-ack 6 and restart/stop/save cases; responses are FC >=128 (C:pkg/dp/ics/dnp3/frame.go:100-129). They are classifications, not validation of a select/execute handshake.

## Milestone distinction and recommended acceptance contracts

### A — TCP/2404 segmentation only

**Verified capability / proposed package wiring:** use existing transport port rules and source-pinning, `ics:{}` or no ics, NFLOG for blocked-flow evidence, and enforcement=true. No decoder, UI protocol semantic editor, or CA/IOA schema needed (C:pkg/cp/config/config.go:780-798; C:pkg/dp/enforce/enforce.go:401-424; R:backend/internal/containd/client.go:570-593).

**Must not claim:** monitoring-only, blocked IEC control commands from an allowed master, IOA/CA restriction, STARTDT intelligence, or IEC104 telemetry classification. Any valid/invalid payload on allowed TCP/2404 is equally allowed (C:pkg/dp/enforce/enforce.go:434-454; C:pkg/dp/engine/decoders.go:22-41).

**Proposed acceptance:** denied enterprise/vendor/other OT cannot establish fresh TCP/2404 to field; authorized master can connect and run monitoring/control in weak lab; hardened package blocks unauthorized *sources*; legitimate telemetry survives. Test fresh and previously established flows separately: current L4 compiler accepts conntrack established before ordinary L4 denies (C:pkg/dp/enforce/enforce.go:187-205). Document restart/conntrack policy at package switches. A can ship separately from B, labeled port-level segmentation.

### B — command-aware, allow monitoring; alert/block control per CA/IOA

**Unavailable today:** no event-producing decoder, IEC match/context fields, whitelist membership, or UI contract (evidence above). Alerts become feasible once decoding/attribute contracts exist; reliable prevention also requires shared dataplane fixes.

**Proposal/open IEC profile, to confirm against authoritative IEC104 specification and simulator interoperability:**

- APCI: start 0x68, validated length, complete APDU boundaries; I/S/U classification; I N(S)/N(R), S acknowledgement N(R); U STARTDT act/con, STOPDT act/con, TESTFR act/con. S/U carry no ASDU and must not be treated as missing-FC commands or unclassified writes.
- ASDU: Type ID, VSQ object count and SQ bit; COT with test/negative flags and originator; common address (CA); each information-object address (IOA). Typical IEC104 profile uses two-byte COT, two-byte CA and three-byte IOA; contract must enforce correct widths including IOA >65535 and distinguish absent fields from zero.
- Monitoring: explicit supported M_* type allowlist, including timed and untimed telemetry; not “everything lacking is_write is read.” Process-management requests needed for monitoring (e.g. C_IC interrogation 100, C_CI counter interrogation 101, C_RD read102) require intentional policy even though named C_*.
- Commands: C_SC single 45/58, C_DC double46/59, C_SE normalized/scaled/float48/49/50 and timed61/62/63. Parse the per-object select/execute bit, command/setpoint value, qualifier and timestamp where present. Do not ignore regulating C_RC47/60, bitstring51/64 or reset/clock/test/parameter/file types merely because first workshop uses fewer commands; unsupported/malformed types need explicit alert/fail-open/fail-closed decisions.
- COT determines activation/confirmation/termination and negative/test semantics; type alone cannot distinguish command request from its confirmation. Derive direction from endpoints/session role and COT, not `eventDirection("response")` alone. Many objects in one ASDU and many APDUs in a TCP segment must all be checked; a permitted first object cannot bless later unauthorized IOAs.
- State: basic select/execute *classification* is sufficient to alert/block both. Enforcing select-before-execute is a distinct transaction feature requiring session+CA+IOA(+type/value), expiry, confirmation handling, negative responses, disconnect cleanup and concurrency tests; existing DNP3 has no such state to reuse.

**Product decision required before estimating full B:** existing block-flow approach shuts down monitoring for up to ten minutes (C:pkg/dp/engine/engine.go:31; runtime_events.go:401-402). Dropping an IEC104 I-frame without reconciling TCP delivery/APCI sequence state is not transparent “remove command, keep telemetry.” Choose (1) alert-only; (2) reject/terminate the violating connection and allow clean reconnect, with explicitly documented monitoring interruption; or (3) a protocol-aware proxy/resequencer for uninterrupted selective filtering, a substantially larger project. NFQUEUE first-command verdict and fragmented/coalesced-message holdback must be correct under whichever preventive design is chosen (C:pkg/dp/capture/nfqueue_linux.go:172-179; C:pkg/dp/dpi/dpi.go:147-178).
