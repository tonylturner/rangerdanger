# IEC104 research — 2026-10-09

## Synthesis

**1. Stacks.** Preferred (assessment): [lib60870-C](https://github.com/mz-automation/lib60870), C99, active v2.4.1 (July 2026), client/server, GI, spontaneous events and command select bits; selection/interlocks remain application logic. GPLv3/commercial dual. [c104](https://github.com/Fraunhofer-FIT-DIEN/iec104-python) adds Python points, GI, events and select/execute handling; GPLv3, maintained, Linux amd64/arm64 wheels. Buying lib60870 does NOT relicense c104.

[thinkgos](https://github.com/thinkgos/go-iecp5) is archived (2023); client/server, GI/events, low-level select encoding. [wendy512](https://github.com/wendy512/iec104) is maintained (v1.0.4, February 2026), Apache wrapper with client/server despite client-only README; GI/events, but convenience commands force direct execution. Both go-iecp5 trees have LGPLv3 licence files versus GPLv3 source headers: clarify before adoption. Mature [j60870/OpenMUC](https://www.openmuc.org/iec-60870-5-104/) is Java client/server, GPLv3/commercial; GI, command/event ASDUs, application-controlled semantics. OpenMUC is the larger GPL Java/OSGi framework.

**Distribution:** Apache can feed a GPLv3 combined work, not convert GPL dependencies to Apache. Public images need corresponding source/build materials and notices. Independent GPL/Apache services may coexist; containers alone provide no exemption. Review before shipping. [FSF](https://www.gnu.org/licenses/gpl-faq.html#MereAggregation)

**2. Architecture.** Representative: SCADA IEC104 client → RTU/gateway server → IEC61850 IEDs, legacy 101/103, Modbus or hardwired I/O. Secondary-substation/RMU RTUs also connect upstream; not all RMUs are telecontrolled. [RTU example](https://www.zivautomation.com/products/distribution-automation-solutions/flexible-modular-rtu-for-secondary-distribution-automation/) **Lab inference:** one primary station, two RMUs; IEC104 northbound, Modbus southbound as labelled simplification; local protection survives SCADA loss. Teach GI/events, double-point status, stale quality, select expiry and feedback.

**3. Physics.** CIGRE European MV: 20 kV/50 Hz, two 110/20-kV transformers, cable/overhead feeders, normally-open ties. An [MIT OpenDSS builder](https://github.com/panas-bhattarai/local-rl-voltvar-study) exists, using BSD-derived data, fixed taps and study-specific PV/tap changes: restore benchmark settings and independently validate. Brochure copyright is separate. Lab choice: 20-kV RMUs/cables, source OLTC; omit line regulators/capbanks, not claim Europe never has them. 10/20 kV are representative. Model overcurrent/earth-fault protection and declare neutral earthing; power flow alone does not prove protection fidelity.

**4. Visibility/training.** [Wireshark/tshark](https://www.wireshark.org/docs/dfref/i/iec60870_asdu.html) decodes IOA, COT, select bit and quality. [Zeek plugin](https://github.com/georgemakrakis/zeek-iec104) is external Spicy, partial ASDU coverage; IEC104 is neither built-in nor in CISA ICSNPP's list. No upstream [Suricata](https://github.com/OISF/suricata/tree/master/rust/src) IEC104 app-layer parser found; TCP/content rules are not semantic decoding. [Snort 3](https://blog.talosintelligence.com/ics-protocol-coverage-snort-3/) DOES have an IEC104 inspector/rule keywords. Use c104 clients/Scapy for isolated lab manipulation; training prevalence unverified. [Industroyer2](https://www.welivesecurity.com/2022/04/12/industroyer2-industroyer-reloaded/) is an IEC104 teaching hook, not software to deploy.

**5. Security.** [62351-3:2023](https://webstore.iec.ch/en/publication/68410) profiles TLS 1.2/1.3; [62351-5:2023](https://webstore.iec.ch/en/publication/65511) secures application exchanges (not just legacy challenge/reply). lib60870/c104 offer open-source TLS, not demonstrated complete current conformance. MZ advertises 60870-5-7:2013 authentication only as a commercial add-on; current mapping is 5-7:2025. No verified open-source current -5 implementation found.

### 1. Stack selection and licensing

- **lib60870-C:** [README.md](https://github.com/mz-automation/lib60870/blob/master/README.md) lists application message types, client/server, redundancy, mbedTLS and the proprietary authentication add-on. [v2.4.1 release](https://github.com/mz-automation/lib60870/releases/tag/v2.4.1) published 2026-07-15; repository pushed 2026-08-31 according to public GitHub metadata. Vendor backing, conformance-related fixes and release history support the maturity assessment, not a blanket certification claim.
- **Application responsibility:** [simple_server.c](https://github.com/mz-automation/lib60870/blob/master/lib60870-C/examples/cs104_server/simple_server.c), interrogation handler and command handler, demonstrates GI replies and command handling; it is an example, not a safe switchgear controller. Select encoding does not itself reserve a device, enforce matching execute, reject expiry, apply interlocks, or prove physical feedback. Define those semantics explicitly.
- **c104:** [README.md:17-63](https://github.com/Fraunhofer-FIT-DIEN/iec104-python/blob/main/README.md) provides client/server examples and GPLv3 declaration; the system-requirements section lists manylinux x86_64/aarch64 and Python >=3.7,<3.13. [Point API](https://iec104-python.readthedocs.io/latest/python/point.html) documents command_mode, SELECT_AND_EXECUTE, selected_by, on_receive and SPONTANEOUS transmit. [v2.2.1](https://github.com/Fraunhofer-FIT-DIEN/iec104-python/releases/tag/v2.2.1) released 2025-04-11; repository pushed 2026-08-06. Native C/C++/mbedTLS underpin this binding: not pure Python; verify wheel/Python pin on both image architectures. Commercial permission for MZ's library does not cover Fraunhofer's separate GPL wrapper automatically.
- **thinkgos:** [README.md:1-23](https://github.com/thinkgos/go-iecp5/blob/master/README.md) explicitly says archived/not maintained and lists client/server; [LICENSE:1-11](https://github.com/thinkgos/go-iecp5/blob/master/LICENSE) remains LGPLv3, but [asdu/information.go:1-3,451-468](https://github.com/thinkgos/go-iecp5/blob/master/asdu/information.go) says GPLv3 and implements select encoding. Public metadata: archived=true, last push 2023-03-04, latest release v1.2.1 on 2022-05-25. [_examples/cs104_server_general/srvGeneral.go:31-54](https://github.com/thinkgos/go-iecp5/blob/master/_examples/cs104_server_general/srvGeneral.go) sends GI confirmation/data/termination and shows commented spontaneous reporting. No complete device-selection state machine was verified. Licence-waiver wording, source headers and licence file conflict: clarify provenance before adopting.
- **wendy512:** [README.md:9,36-39](https://github.com/wendy512/iec104/blob/master/README.md) says client, links server/client tests and declares Apache. [tests/iec104_test.go:5-7,29-34,85-88](https://github.com/wendy512/iec104/blob/master/tests/iec104_test.go) starts a server and issues GI. [tests/server_handle.go:17-39,345-358](https://github.com/wendy512/iec104/blob/master/tests/server_handle.go) emits GI/spontaneous ASDUs; generic control example is a TODO/echo. [client/core.go:144-161](https://github.com/wendy512/iec104/blob/master/client/core.go) fixes InSelect=false. [go.mod:7](https://github.com/wendy512/iec104/blob/master/go.mod) imports go-iecp5 v1.2.5; [dependency LICENSE:1-11,79-114](https://github.com/wendy512/go-iecp5/blob/v1.2.5/LICENSE) is LGPLv3, but [dependency asdu/information.go:1-3](https://github.com/wendy512/go-iecp5/blob/v1.2.5/asdu/information.go) says GPLv3. Do not claim Apache-only or conclusively LGPL-only until clarified. LGPL interpretation still requires notices and recombination/source provisions. Wrapper v1.0.4 released/pushed 2026-02-03. Assess as lower-assurance until independently tested.
- **j60870:** [vendor overview](https://www.openmuc.org/iec-60870-5-104/) states client/server and GPLv3/negotiated proprietary licence. [user guide](https://www.openmuc.org/j60870/user-guide/) lists GI, command and measurement ASDUs for both roles. [changelog](https://www.openmuc.org/j60870/changelog/) has 1.8.0 dated 2026-07-17, minimum Java 11, decoding and START/STOP fixes; history starts in 2014. GI and unsolicited event messages are representable; server process state and full select/execute semantics require application review. No current -5 security conformance was verified.
- **OpenMUC:** [user guide](https://www.openmuc.org/openmuc/user-guide/) describes GPL Java/OSGi framework, IEC104 driver, REST and other protocol services. [framework changelog](https://www.openmuc.org/openmuc/changelog/) records v0.20.0 (2024-08-30), updating j60870 to 1.7.2. Framework and standalone library release trains differ; do not assume their bundled versions match.
- **Licence reasoning:** [Apache compatibility statement](https://www.apache.org/licenses/GPL-compatibility.html), [GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html#MereAggregation) and [LGPLv3 section 4](https://www.gnu.org/licenses/lgpl-3.0.html) support the directional compatibility/aggregation distinction. This is engineering triage, not legal advice. Independent-process classification depends on actual coupling. Public image delivery needs compliant source availability for the exact shipped binaries, not merely an upstream homepage link. A commercially licensed C adapter or an explicitly GPL simulator component are options; the product owner must choose.

### 2. Architecture and teaching scope

- **Gateway reality:** [ZIV MV Flexible RTU](https://www.zivautomation.com/products/distribution-automation-solutions/flexible-modular-rtu-for-secondary-distribution-automation/) describes secondary-substation control, IEC61850 client/server, IEC101/104, IEC103 and Modbus. [ABB secondary-substation guide, section 5](https://new.abb.com/docs/librariesprovider27/default-document-library/gu_smart-grid_cabina-secondaria%28en%29-_1vcp000620---digiprint.pdf?sfvrsn=2) describes IEC101/Modbus-RTU to IEC104/Modbus-TCP gateway paths. [OMICRON](https://www.omicronenergy.com/en/video-channel/?tx_solr%5Bfilter%5D%5B0%5D=product%3AStationScout&tx_solr%5Bfilter%5D%5B1%5D=language%3AEnglish) explicitly trains IEC61850↔IEC104 RTU signal translation. These are representative equipment/workflow examples, not a survey of every European DSO.
- **Inference:** Keep control-centre, station-control, field, engineering/vendor and physical-model boundaries distinct. One IEC104 station gateway plus local Modbus devices is credible for an initial segmentation lab; advertise it as mixed-generation/legacy, not a full IEC61850 digital station. IEC101/103 serial traffic would require explicit serial/gateway emulation; putting those protocol labels on ordinary TCP traffic would misteach.
- **Suggested vertical slice:** measured U/I/P/Q with units and quality, double-point breaker status with timestamps, feeder open/close via select→execute→confirmation→feedback, GI snapshot then event updates, bounded selection expiry, local/remote mode and interlocks. Loss of conduit must affect operator visibility independently of physical/local protection. These are proposed acceptance criteria, not implementation claims.
- **Avoid false protection equivalence:** RTU telemetry is not the protection loop; IEC61850 MMS monitoring/control and GOOSE interlocking/tripping are distinct. A Docker power-flow lab need not claim sampled-values/process-bus or protection timing fidelity.

### 3. Reference network and process fidelity

- **Concrete OpenDSS availability:** [local-rl-voltvar-study README.md:54-66,254-259,287-294,334-337](https://github.com/panas-bhattarai/local-rl-voltvar-study/blob/main/README.md) describes a 20-kV/50-Hz CIGRE OpenDSS implementation, radial ties, study tap modification, generator module and limitations. [LICENSE:1-19](https://github.com/panas-bhattarai/local-rl-voltvar-study/blob/main/LICENSE) is MIT. [src/cigre_dss.py:1-29,61-89,121](https://github.com/panas-bhattarai/local-rl-voltvar-study/blob/main/src/cigre_dss.py) implements frequency before circuit creation, 110/20-kV transformers and benchmark taps. The builder's default retains brochure taps; the PV study overrides TR1. Its validation precision is author-reported and was NOT independently reproduced.
- **Data lineage:** that builder credits [CIGRE-MV-PSCAD](https://github.com/panas-bhattarai/CIGRE-MV-PSCAD), BSD-3-Clause, for the JSON extraction; preserve that provenance/licence instead of calling all inputs MIT. The original CIGRE brochure remains copyrighted; repository licensing is not permission to redistribute the brochure. No formal rights clearance of the extracted dataset was performed.
- **Established alternative:** [pandapower CIGRE documentation](https://pandapower.readthedocs.io/en/latest/networks/cigre.html) offers create_cigre_network_mv and documents network counts; [pandapower source licence](https://github.com/e2nIEE/pandapower/blob/develop/LICENSE) is BSD-3-Clause. Porting and checking equivalent OpenDSS results remains work; it is not native .dss distribution.
- **Typical voltage/equipment, not universal:** [Siemens HG11.01, p.4](https://support.industry.siemens.com/cs/attachments/109745538/HG11.01_EN_20190603.pdf) discusses 10/20-kV distribution and national variation. [ABB RMU catalogue, pp.83-86](https://library.e.abb.com/public/7321f21b8bb24150932c2670d4571be7/SafeRing_SafePlus%2012-24kV_Catalogue_EN_1YVA000022_REV%20B%2003-2021.pdf) describes remote switchgear and directional/non-directional fault indicators, dependent on isolated/compensated/resistance/solid earthing.
- **Protection:** [ABB REJ603](https://www.abb.com/global/en/areas/electrification/medium-voltage/grid-components/secondary-protection-relays/rej603) describes RMU/secondary overcurrent, earth-fault and transformer protection. Lab inference: primary feeder breaker clears faults; RMU switches isolate/reconfigure; transformer branch may use fuse-switch or breaker. Do not assume every switch is fault-interrupting. OLTC at the primary transformer is a sensible simplification; source builders use fixed taps, so operational tap control must be added and validated.
- **Limit:** A 50-Hz load-flow model alone cannot validate compensated-neutral earth faults, relay selectivity, arc dynamics or millisecond trip timing. Declare an earthing/protection simplification, or add those models before claiming fidelity. Omitting line regulators and switched feeder capacitors is a package choice, not a continent-wide absence claim.

### 4. Student tooling

- **Wireshark:** [APCI reference](https://www.wireshark.org/docs/dfref/i/iec60870_104.html) and [ASDU reference](https://www.wireshark.org/docs/dfref/i/iec60870_asdu.html) expose typeid, causetx, addr, ioa, sco.se/dco.se, quality and timestamps. Tshark offers headless decoding; field names differ from older dissector examples, so pin captures and CLI exercises to the shipped version.
- **Zeek:** [georgemakrakis README.md:1-28,50-125](https://github.com/georgemakrakis/zeek-iec104/blob/master/README.md) is an external Spicy plugin with iec104.log and an incomplete supported-ASDU matrix (e.g. time-tagged double point and several setpoints omitted). [Zeek built-in analyzer directory](https://github.com/zeek/zeek/tree/master/src/analyzer/protocol) contains no IEC104 analyzer; [ICSNPP README](https://github.com/cisagov/ICSNPP) lists no IEC104 parser. README's “seven parsers” sentence is stale relative to its expanded package list; do not use that count. Plugin compatibility/licence and exact desired ASDUs need a pinned build check.
- **Suricata:** No IEC104 module found in current [rust/src](https://github.com/OISF/suricata/tree/master/rust/src), [src](https://github.com/OISF/suricata/tree/master/src), or [configuration documentation](https://docs.suricata.io/en/latest/configuration/suricata-yaml.html). This is bounded negative evidence, not proof no third-party fork exists. TCP port/byte rules are possible but must handle stream segmentation and multiple ASDUs; do not label them a complete parser.
- **Snort:** [Talos inspector article](https://blog.talosintelligence.com/ics-protocol-coverage-snort-3/) and [Snort 3 manual](https://github.com/snort3/snort3/blob/master/doc/user/snort_user.text) confirm an IEC104 service inspector with iec104_apci_type and iec104_asdu_func. [SID 1:41079](https://www.snort.org/rule_docs/1-41079) detects IEC104 crossing EXTERNAL_NET; it is a policy rule, not attack attribution. Ruleset redistribution terms are separate from the engine's open-source status.
- **Training tooling:** [Scapy IEC104 module](https://github.com/secdev/scapy/blob/master/scapy/contrib/scada/iec104/__init__.py) supplies protocol layers/objects, GPL-2.0-only; not a complete safe IEC104 session/controller by itself. c104 client scripts can generate controlled lab scenarios. No evidence establishes a universally “commonly used” attack suite; avoid that claim. [ESET original investigation](https://www.welivesecurity.com/2022/04/12/industroyer2-industroyer-reloaded/) confirms original Industroyer had 101/104/61850/OPC modules and Industroyer2 specifically implements 104. Teach legitimate-command abuse without shipping malware.

### 5. Security editions and support

- **Current editions:** [IEC62351-3:2023](https://webstore.iec.ch/en/publication/68410) defines endpoint TLS1.2/1.3 profiles, including certificate/revocation/session/security-event requirements; external bump-in-the-wire devices are outside its scope. [IEC62351-5:2023](https://webstore.iec.ch/en/publication/65511) replaces 2013 challenge/reply/aggressive mode with association-based secure data exchange and authenticated encryption. [IEC TS60870-5-7:2025](https://webstore.iec.ch/en/publication/87773) maps those requirements to 101/104 and includes RBAC considerations. Therefore older “secure authentication” descriptions cannot silently stand for current edition conformance.
- **Open-source transport:** [c104 TransportSecurity API](https://iec104-python.readthedocs.io/latest/python/transportsecurity.html) exposes server/client TLS, certificate validation, allowlisted peer certificates, ciphers, TLS versions and session controls. [MZ README](https://github.com/mz-automation/lib60870/blob/master/README.md) says “most” -3 TLS features, not all current edition requirements; authentication add-on explicitly references 5-7:2013 and is commercial. No publicly inspectable complete current -5 implementation in the examined stacks was verified.
- **Inference:** offer plaintext segmentation exercise and an optional endpoint-mutual-TLS comparison. TLS blocks passive command decoding on the encrypted conduit, so use endpoint logs or a clearly authorized plaintext/decrypted observation point. A TLS tunnel is useful defence but not automatic IEC62351 compliance; select-before-operate is not authentication.

This is a future validation plan, not observed success.
