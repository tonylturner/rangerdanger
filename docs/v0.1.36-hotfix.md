# v0.1.36 workshop errata

Historical release guidance. For v0.2.0 use the package-aware
[upgrade procedure](quickstart.md#upgrading-to-v020), not the installer
sequence below. The current US package ports the factual corrections into
both source YAML and generated steps; stable IDs, not Stage titles, own
injection. In v0.1.36 a design-plan appendix remained visible but was not the applied policy. Current Lab 2.2 can compile and apply the student's plan, with
Hardened as a reference alternative; see [the workshop overview](workshop-overview.md#the-exercises).
The reference-only limitations and instructions below describe v0.1.36,
not current plan behavior.

v0.1.36 is a **full image release**. All 16 first-party images are rebuilt
and `latest` moves; it includes corrected lab content, embedded UI routing,
vendor desktop startup and the backend fixes below. The frontend source
was unchanged for that release; its application limitations and lab
guidance below are retained as historical errata.

## How to update

Use the normal [online install or release update](quickstart.md#upgrading-to-v020)
procedure, including the PowerShell steps. Setup's refresh path stops the
installed stack before pulling the new images and runs a workshop reset;
save your evidence and back up local work first. This release is not an
image-preserving patch.

## SSD / offline update

New offline installs use the normal [full SSD bundle](workshop-ssd.md#initial-stage).
Existing installs can use the normal [delta workflow](workshop-ssd.md#delta-staging)
and its generated `DELTA-README.md` (backup, image import, restart and
rollback). A v0.1.35 → v0.1.36 delta is close to a full set because every
first-party image is rebuilt. The repository-update helper alone does not
install this release's images.

On Windows, verify LF line endings and executable visibility for both
mounted init scripts (`scripts/vendor-jump-services.sh` and
`scripts/set-gateway.sh`); see [quickstart troubleshooting](quickstart.md#common-errors).
The historical recommendation was to prefer a WSL Linux-filesystem (ext4)
checkout. That layout is **unsupported for current Windows installs**:
use Docker Desktop WSL2 with a physical local-drive checkout, not `\\wsl$`,
as specified in the [current Windows requirements](quickstart.md#windows-docker-desktop-wsl2-only).
The following startup caveat describes the old release: native NTFS and WSL startup
both need manual startup checks; do not assume the image's executable bit
repairs a non-executable bind mount.

## Your enforcement self-check

**RD-01:** Keep your plan as a design artifact. For this workshop apply Hardened reference, not Apply Your Plan; a green apply/banner is not enforcement evidence. The report is your proof: authorized 8/8, unauthorized blocked 11/11, no skipped tests, plus healthy HMI.

**RD-02:** Only use the Hardened reference for the DNP3 re-test. A TCP PASS
or the dnp3-dpi selection does not prove FC5/6 rejection. Enforcement proof is
device state: after the Kali Direct Operate times out, the RTAC register read
must still show `reclose_enabled` = `1`. Record that read with the result.
See RD-24 for the enforcement/visibility distinction.

**RD-24:** The L4 source pin enforces; DPI detects and logs.
Lab 2.3 distinguishes enforcement checks from optional visibility
checks. Verify current device state and preserve the evidence, not just
policy labels. Restore healthy state with Supervisory Control → Enable
Reclose (or Reset Lab, then re-apply Hardened reference) before Validate.
Historical training writes can leave Validate at PARTIAL even after
restoration; PARTIAL with every device-state row ✓ is expected in that
case (RD-19). The Lab 2.4 report is a TCP reachability matrix (its DNP3
row is an FC1 read; no row sends a control write), not protocol-level
enforcement proof.

**RD-25:** containd web-UI rule **Create** and **Delete** save the running
config but do not enforce it until **Commit**: deleting the weak
`enterprise-to-vendor` rule leaves 3389/5900 open from Kali until `commit`
at `containd#` (or **Commit** on the **Configuration** page). Lab 2.2's
Stage 2 and Stage 3 text now says to commit after the last edit and, on the
Advanced track, to commit before probing RDP/VNC.

**RD-26:** On these images the recloser records a Modbus write only as
`modbus-tcp` (Electrical Detail → Mid-Feeder Recloser → Last Command); it
does not record the peer address, and the documented `mbpoll` path adds no
Command Audit row (only Execute Step writes `10.20.20.10` there). The one
student-visible surface that attributes the live write is the containd UI:
/containd/, log in `containd` / `containd`, **NETWORK → Sessions**, rows with
SRC `10.20.20.10` to DST `10.40.40.21` DPORT `502`. Open Sessions before the
write, raise the list limit above 500 rows and filter on `10.20.20.10` so the
vendor row is visible. Rows expire in about 17 seconds; re-run the write if
they are gone.
Flows, Events and the Network Map's Live DPI Events show nothing under the
weak baseline. Lab 2.3-bonus step 3 and its attribution decision now use
Sessions.

**RD-03:** Validate Exercise checks operational state only in these images; it may PASS and auto-complete with no report or a FAIL report. Check the actual report for 8 authorized passes, 11 unauthorized blocks and zero skipped, plus healthy HMI. Save the report, PCAP and notes. Trust the report, not the banner.

**RD-18:** In these images, Execute may report a red failure/BLOCKED when rejecting an unauthorized action, and it will not advance automatically. That label is not a packet verdict. Run the documented real protocol retest, inspect unchanged healthy device/HMI state and firewall evidence, record the result, then Mark Complete. A refused/timeout connection without state/evidence is not enough to claim DPI.
Execute can reject an action before any packet is sent; a failed expected-block
probe can also log BLOCKED even when the destination was reachable. Read details.

**RD-19:** PARTIAL may include successful attacks from earlier weak-policy training or smoke runs. Record current retest timestamps; compare those events with earlier weak-policy writes. Check for healthy restored state and blocked current attempts; do not clear audit or repeatedly reset/re-attack to make the banner green. Current successful unauthorized writes still fail.

The former header instructions to override generated DNP3/Modbus/export/SSH
snippets are moot. The source examples below remain instructor references.

- **Cross-zone nmap:** use `nmap -Pn -p ...` in the baseline, manual
  validation, and vendor-pivot scans. Host discovery can report "0 hosts up"
  across the firewall even when TCP services are reachable. Compare `open`
  under Weak baseline with `filtered` under Hardened reference; host-down
  output is not denial evidence. Run the vendor remote-access scans from
  Kali, not from the vendor jump box itself.

- **RD-05:** put every `dnp3poll` option before the endpoint, with duration
  units. Use the correct outstation address: relay 1, recloser 2, regulator 3,
  capbank 4. Do not change `dnp3cmd` syntax; its parser differs.

  ```sh
  # RTAC terminal, allowed field path
  dnp3poll -a 2 -t 3s 10.40.40.21:20000
  dnp3poll -a 3 -t 3s 10.40.40.22:20000
  ```

- **RD-06:** FC2 (`mbpoll -t 1`) is unsupported. Relay/capbank FC1 coil reads
  use at most four coils. Keep device-specific regulator/RTAC reads and attack
  writes unchanged. Negative tests also need valid requests: protocol errors
  are not firewall blocks.

  ```sh
  # RTAC terminal -> relay, allowed under reference
  mbpoll -a 1 -r 1 -c 4 -1 -t 0 10.40.40.20
  # Eng WS terminal -> capbank, WEAK policy only
  mbpoll -a 1 -r 1 -c 4 -1 -t 0 10.40.40.23
  ```

- **RD-07:** Choose/apply the intended policy explicitly in the policy panel,
  then Execute Step verifies its label without replacing it. This check is
  not enforcement proof; run the report/retests. The workshop uses reference
  enforcement; custom plans are design artifacts.
- **RD-08:** At containd# run `export config` to print JSON; it does not support shell redirection. Copy that JSON to your evidence document. For this release, author/review using Configuration in the direct http://localhost:9080 UI or use Hardened reference. The CLI JSON-file edit/import exercise is deferred; do not edit a file the CLI never created.
  Validate the copied JSON on your workstation with `python3 -m json.tool`.
  Browser export/download is optional; the copied CLI JSON is your evidence.
- **RD-10/11:** the prescribed baseline capture is read-only: accept
  `NOT_OBSERVED` for writes unless the actual capture contains extra student
  commands. The Vendor/DMZ → OT filter may also be empty if that path was not
  exercised during the capture window; record `NOT_OBSERVED`, not denial.
  Preserve A/E autonomous and F/G intra-zone operations. B/C HTTP8080
  and D FUXA1881 are blocked by the hardened reference **in this version**,
  not permanently retired. Engineering/vendor access after hardening uses
  RTAC SSH/HTTPS; no encrypted replacement editor is promised.
- **RD-12:** Selections save automatically. Do not use Execute Step for this decision in this release. Finish selecting a feasible plan, click Mark Complete, then record your reflection.
- **RD-13/14:** select the named source terminal, not your host terminal.
  Firewall terminals start at `containd#`; type `shell` before Linux/tcpdump
  commands and `containd cli` to return. Never start the containd daemon.
  If a terminal is missing, use Network Map → exact host → Terminal.

For manual encrypted-management checks in Lab 2.4, use `ssh -o ConnectTimeout=3 rangerdanger@10.30.30.20 hostname`, password `rangerdanger`, from the documented vendor/engineering source; verify host identity before accepting its first lab key.

## Quick help and remaining limitations

Follow Exercises **1.2 → 1.3 → 1.4 → 2.2 → 2.3 → 2.4**, then the bonus.
Use Feeder HMI for operations, Network Map for hosts/terminals, Workshop Status
for services. containd credentials are `containd` / `containd`; vendor/RTAC
SSH or RDP is `rangerdanger` / `rangerdanger`; OpenPLC is `openplc` / `openplc`.
These are public lab credentials, not production secrets.

v0.1.36 fixes embedded containd routing (RD-04) and vendor desktop
startup (RD-09). The Network Map now links directly to `/containd/` and
`/apps/openplc/`; the backend session API reads containd conntrack rather
than a nonexistent sessions endpoint. If these fail after installing the
full release, stop for instructor diagnosis; direct http://localhost:9080
remains a firewall access path. Do not apply the old manual symlink workaround instead of installing
the full v0.1.36 release.

Save PCAPs from `/home/abc/pcaps/` in the engineering desktop before resetting;
generated reports use timestamped filenames, manual validation uses
`validation.pcap`. Allow roughly 2–3 seconds for physics/HMI updates.

Remaining application limitations: exercise-header Reset Lab restores weak policy
and devices and deletes captures, while keeping notes/checkmarks; HMI Reset
lab resets the load model only (RD-20). Reset Progress separately clears
exercise notes/checkmarks/log, not running devices or the shared plan.
Reload may open step 1 without losing saved work; select the previous step
in the navigator (RD-21). OpenPLC Programs timeout is not fixed or diagnosed
by this release (RD-22); use HMI/RTAC evidence, not PLC restarts.

**Not covered by automated tests:** live report and protocol
retests, real browser login/desktop input and saved downloads, plus fresh
vendor mount/startup on macOS and Windows (NTFS and WSL ext4). Static content
tests are not runtime enforcement or GUI proof.
