# v0.1.36-rc.2 workshop errata

This is a **repository-only update using your existing v0.1.35 images**:
no pull, no rebuild. It corrects lab content, embedded firewall routing and
vendor desktop startup. The application limitations below remain in the
frozen images; the revised workflow mitigates them, not repairs them.

## How to update

Save captures, notes and desktop work first: the vendor desktop session will
end during its targeted recreation. Resolve/back up source edits shown by
`git status --short` before switching. Keep `.env`, `VERSION`, `data/`,
`backend/data/` and browser storage unchanged. Confirm cached image identities
match the installed v0.1.35 images; stop if they do not, rather than pulling.

**Online, from your existing installation:**

```sh
git fetch origin tag v0.1.36-rc.2 && git checkout --detach v0.1.36-rc.2 && ./scripts/apply-repo-update.sh
```

**Windows PowerShell:** stop if either Git command fails.

```powershell
git fetch origin tag v0.1.36-rc.2
if ($LASTEXITCODE -ne 0) { throw "Fetch failed; stop here" }
git checkout --detach v0.1.36-rc.2
if ($LASTEXITCODE -ne 0) { throw "Checkout failed; stop here" }
.\scripts\apply-repo-update.ps1
```

The PowerShell twin is `scripts/apply-repo-update.ps1`. On Windows, verify LF
line endings and executable visibility for both mounted init scripts
(`scripts/vendor-jump-services.sh` and `scripts/set-gateway.sh`); see
[quickstart troubleshooting](quickstart.md). Prefer a WSL Linux-filesystem
(ext4) checkout. Native NTFS and WSL startup both need instructor sign-off;
do not assume the image's executable bit repairs a non-executable bind mount.

## SSD / offline update

Use the instructor's **repository-only** update directory containing
`rangerdanger-v0.1.36-rc.2.tgz`, `rangerdanger-v0.1.36-rc.2.bundle`,
`SHA256SUMS` and `REPO-UPDATE-README.md`. These are not image deltas.
Keep the existing v0.1.35 images and `VERSION=latest`; do not load rc images.
The v0.1.35 install does not include the update helper: obtain the rc.2 files
by the appropriate path below **before** running it.

### macOS/Linux: checksum first

Set the directory containing the update artifacts, then verify both files.
**Stop on any checksum failure.** On Linux, `sha256sum -c SHA256SUMS` is
an equivalent check.

```sh
SSD=/Volumes/WORKSHOP_SSD
(cd "$SSD" && shasum -a 256 -c SHA256SUMS)
```

**Archive install (no `.git`):** back up any local source edits first;
extraction overwrites tracked files and cannot check edits. Keep `.env`,
`data/`, `backend/data/` and captures. For the existing `~/rangerdanger`:

```sh
tar xzf "$SSD/rangerdanger-v0.1.36-rc.2.tgz" -C ~ &&
cd ~/rangerdanger &&
./scripts/apply-repo-update.sh --from-tarballs "$SSD"
```

The helper prints that it skipped the Git tracked-file guard when `.git`
is absent. Local-image checks, Compose `--pull never` support and `config -q`
validation still apply; Git is not required for an archive install.

**Git clone (offline):** use the bundle, never extract the archive over a
clone. Back up/resolve tracked edits before switching; the helper's Git
checkout/cleanliness guard is unchanged.

```sh
cd ~/rangerdanger &&
git fetch "$SSD/rangerdanger-v0.1.36-rc.2.bundle" tag v0.1.36-rc.2 &&
git checkout --detach v0.1.36-rc.2 &&
./scripts/apply-repo-update.sh --from-tarballs "$SSD"
```

### Windows PowerShell SSD steps

Verify both checksums first; stop if any command fails:

```powershell
$SSD = 'D:\WORKSHOP_SSD'
Get-Content (Join-Path $SSD 'SHA256SUMS') | ForEach-Object {
    $Expected, $Name = $_ -split '  ', 2
    if ((Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $SSD $Name)).Hash -ne $Expected) {
        throw "Checksum mismatch: $Name"
    }
}
```

For an **archive install**, Windows 10 1803+ provides `tar.exe`. Back up
source edits first; extract over the existing `$HOME\rangerdanger`:

```powershell
tar.exe -xzf (Join-Path $SSD 'rangerdanger-v0.1.36-rc.2.tgz') -C $HOME
if ($LASTEXITCODE -ne 0) { throw "Extraction failed; stop here" }
Set-Location -LiteralPath (Join-Path $HOME 'rangerdanger') -ErrorAction Stop
.\scripts\apply-repo-update.ps1 -FromTarballs $SSD
```

For an **offline Git clone**, do not extract; from the existing checkout:

```powershell
git fetch (Join-Path $SSD 'rangerdanger-v0.1.36-rc.2.bundle') tag v0.1.36-rc.2
if ($LASTEXITCODE -ne 0) { throw "Fetch failed; stop here" }
git checkout --detach v0.1.36-rc.2
if ($LASTEXITCODE -ne 0) { throw "Checkout failed; stop here" }
.\scripts\apply-repo-update.ps1 -FromTarballs $SSD
```

For every SSD path, `--from-tarballs` / `-FromTarballs` is **required** to
select `docker-compose.offline.yml`. The helper does not import tarballs,
read the SSD's `.version`, or auto-detect the installation mode.

The helper restarts backend and proxy, and recreates only `vendor_jump` with
`--no-deps --no-build --pull never --force-recreate`. It does not use `down -v`
or `--renew-anon-volumes`. Do not replace it with a full-stack down/up.
Do not run `./setup.sh --version v0.1.36-rc.2`: that selects rc images, not
this repo-only update. Never change `VERSION` to rc.2 for this procedure.

and this page override the stale generated snippets, even when an old command

- **Cross-zone nmap:** use `nmap -Pn -p ...` in the baseline, manual
  validation, and vendor-pivot scans. Host discovery can report "0 hosts up"
  across the firewall even when TCP services are reachable. Compare `open`
  under Weak baseline with `filtered` under Hardened reference; host-down
  output is not denial evidence. Run the vendor remote-access scans from
  Kali, not from the vendor jump box itself.

- **RD-05:** put every `dnp3poll` option before the endpoint, with duration
  units. Use the correct outstation address: relay 1, recloser 2, regulator 3,
  capbank 4. Do not change `dnp3cmd` syntax; its parser differs.

  ```sh

  dnp3poll -a 2 -t 3s 10.40.40.21:20000
  dnp3poll -a 3 -t 3s 10.40.40.22:20000
  ```

  use at most four coils. Keep device-specific regulator/RTAC reads and attack

  ```sh

  mbpoll -a 1 -r 1 -c 4 -1 -t 0 10.40.40.20

  mbpoll -a 1 -r 1 -c 4 -1 -t 0 10.40.40.23
  ```

instructor diagnosis; direct http://localhost:9080 remains a firewall access
