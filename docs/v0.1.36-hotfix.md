# v0.1.36-rc.3 workshop errata

This is a **repository-only update using your existing v0.1.35 images**:
no pull, no rebuild. It corrects lab content, embedded firewall routing and
vendor desktop startup. The application limitations below remain in the
frozen images; the revised workflow mitigates them, not repairs them.

## How to update

Save captures, notes and desktop work first: the vendor desktop session will
end during its targeted recreation. Resolve/back up source edits shown by
`git status --short` before switching. Keep `.env`, `VERSION`, `data/`,
`backend/data/` and browser storage unchanged. Confirm cached image identities
match the installed v0.1.35 images; stop if they do not, rather than pulling.

**Online, from your existing installation:**

```sh
git fetch origin tag v0.1.36-rc.3 && git checkout --detach v0.1.36-rc.3 && ./scripts/apply-repo-update.sh
```

**Windows PowerShell:** stop if either Git command fails.

```powershell
git fetch origin tag v0.1.36-rc.3
if ($LASTEXITCODE -ne 0) { throw "Fetch failed; stop here" }
git checkout --detach v0.1.36-rc.3
if ($LASTEXITCODE -ne 0) { throw "Checkout failed; stop here" }
.\scripts\apply-repo-update.ps1
```

The PowerShell twin is `scripts/apply-repo-update.ps1`. On Windows, verify LF
line endings and executable visibility for both mounted init scripts
(`scripts/vendor-jump-services.sh` and `scripts/set-gateway.sh`); see
[quickstart troubleshooting](quickstart.md). Prefer a WSL Linux-filesystem
(ext4) checkout. Native NTFS and WSL startup both need manual startup checks;
do not assume the image's executable bit repairs a non-executable bind mount.

## SSD / offline update

Use the instructor's **repository-only** update directory containing
`rangerdanger-v0.1.36-rc.3.tgz`, `rangerdanger-v0.1.36-rc.3.bundle`,
`SHA256SUMS` and `REPO-UPDATE-README.md`. These are not image deltas.
Keep the existing v0.1.35 images and `VERSION=latest`; do not load rc images.
The v0.1.35 install does not include the update helper: obtain the rc.3 files
by the appropriate path below **before** running it.

### macOS/Linux: checksum first

Set the directory containing the update artifacts, then verify both files.
**Stop on any checksum failure.** On Linux, `sha256sum -c SHA256SUMS` is
an equivalent check.

```sh
SSD=/Volumes/WORKSHOP_SSD
(cd "$SSD" && shasum -a 256 -c SHA256SUMS)
```

**Archive install (no `.git`):** back up any local source edits first;
extraction overwrites tracked files and cannot check edits. Keep `.env`,
`data/`, `backend/data/` and captures. For the existing `~/rangerdanger`:

```sh
tar xzf "$SSD/rangerdanger-v0.1.36-rc.3.tgz" -C ~ &&
cd ~/rangerdanger &&
./scripts/apply-repo-update.sh --from-tarballs "$SSD"
```

The helper prints that it skipped the Git tracked-file guard when `.git`
is absent. Local-image checks, Compose `--pull never` support and `config -q`
validation still apply; Git is not required for an archive install.

**Git clone (offline):** use the bundle, never extract the archive over a
clone. Back up/resolve tracked edits before switching; the helper's Git
checkout/cleanliness guard is unchanged.

```sh
cd ~/rangerdanger &&
git fetch "$SSD/rangerdanger-v0.1.36-rc.3.bundle" tag v0.1.36-rc.3 &&
git checkout --detach v0.1.36-rc.3 &&
./scripts/apply-repo-update.sh --from-tarballs "$SSD"
```

### Windows PowerShell SSD steps

Verify both checksums first; stop if any command fails:

```powershell
$SSD = 'D:\WORKSHOP_SSD'
Get-Content (Join-Path $SSD 'SHA256SUMS') | ForEach-Object {
    $Expected, $Name = $_ -split '  ', 2
    if ((Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $SSD $Name)).Hash -ne $Expected) {
        throw "Checksum mismatch: $Name"
    }
}
```

For an **archive install**, Windows 10 1803+ provides `tar.exe`. Back up
source edits first; extract over the existing `$HOME\rangerdanger`:

```powershell
tar.exe -xzf (Join-Path $SSD 'rangerdanger-v0.1.36-rc.3.tgz') -C $HOME
if ($LASTEXITCODE -ne 0) { throw "Extraction failed; stop here" }
Set-Location -LiteralPath (Join-Path $HOME 'rangerdanger') -ErrorAction Stop
.\scripts\apply-repo-update.ps1 -FromTarballs $SSD
```

For an **offline Git clone**, do not extract; from the existing checkout:

```powershell
git fetch (Join-Path $SSD 'rangerdanger-v0.1.36-rc.3.bundle') tag v0.1.36-rc.3
if ($LASTEXITCODE -ne 0) { throw "Fetch failed; stop here" }
git checkout --detach v0.1.36-rc.3
if ($LASTEXITCODE -ne 0) { throw "Checkout failed; stop here" }
.\scripts\apply-repo-update.ps1 -FromTarballs $SSD
```

For every SSD path, `--from-tarballs` / `-FromTarballs` is **required** to
select `docker-compose.offline.yml`. The helper does not import tarballs,
read the SSD's `.version`, or auto-detect the installation mode.

The helper restarts backend and proxy, and recreates only `vendor_jump` with
`--no-deps --no-build --pull never --force-recreate`. It does not use `down -v`
or `--renew-anon-volumes`. Do not replace it with a full-stack down/up.
Do not run `./setup.sh --version v0.1.36-rc.3`: that selects rc images, not
this repo-only update. Never change `VERSION` to rc.3 for this procedure.

## Your enforcement self-check

**RD-01:** v0.1.36-rc.3 uses the v0.1.35 application images. Keep your plan as a design artifact. For this workshop apply Hardened reference, not Apply Your Plan; a green apply/banner is not enforcement evidence. The report is your proof: authorized 8/8, unauthorized blocked 11/11, no skipped tests, plus healthy HMI.

**RD-02:** Only use the Hardened reference for the DNP3 re-test. A TCP PASS
or the dnp3-dpi selection does not prove FC5/6 rejection. Enforcement proof is
device state: after the Kali Direct Operate times out, the RTAC register read
must still show `reclose_enabled` = `1`. Record that read with the result.
See RD-24 for what an RTAC-origin write does on these images.

**RD-24:** On these images the **L4 source pin is the control that enforces**.
The reference DNP3 rule allows the RTAC reads only (FC1), and the firewall
records a Direct Operate sent from the RTAC as a DPI event, but it does not
stop that write. From the **RTAC terminal under Hardened reference**,

```sh
dnp3cmd 10.40.40.21:20000 -a 2 crob 1 latch-off
```

returns `Result: SUCCESS` and auto-reclose turns off. Lab 2.3 now presents
that RTAC run as an optional visibility check with its expected result; its
keyed answers name the source pin as the blocking layer. Restore with
Supervisory Control → Enable Reclose (or Reset Lab, then re-apply Hardened
reference) before Validate. Validate then reports PARTIAL even after the
restore - its audit row counts that write (and earlier weak-baseline writes)
as unauthorized commands that reached field devices - and the lab says so:
PARTIAL with every device-state row ✓ is the expected result (RD-19). The Lab 2.4 report is a TCP reachability matrix
(its DNP3 row is an FC1 read; no row sends a control write), so a green report
is not protocol-level enforcement proof either.

**RD-25:** containd web-UI rule **Create** and **Delete** save the running
config but do not enforce it until **Commit**: deleting the weak
`enterprise-to-vendor` rule leaves 3389/5900 open from Kali until `commit`
at `containd#` (or **Commit** on the **Configuration** page). Lab 2.2's
Stage 2 and Stage 3 text now says to commit after the last edit and, on the
Advanced track, to commit before probing RDP/VNC.

**RD-26:** On these images the recloser records a Modbus write only as
`modbus-tcp` (Electrical Detail → Mid-Feeder Recloser → Last Command); it
does not record the peer address, and the documented `mbpoll` path adds no
Command Audit row (only Execute Step writes `10.20.20.10` there). The one
student-visible surface that attributes the live write is the containd UI:
/containd/, log in `containd` / `containd`, **NETWORK → Sessions**, rows with
SRC `10.20.20.10` to DST `10.40.40.21` DPORT `502`. They appear within a few
seconds and expire after about 2 minutes; re-run the write if they are gone.
Flows, Events and the Network Map's Live DPI Events show nothing under the
weak baseline. Lab 2.3-bonus step 3 and its attribution decision now use
Sessions.

**RD-03:** Validate Exercise checks operational state only in these images; it may PASS and auto-complete with no report or a FAIL report. Check the actual report for 8 authorized passes, 11 unauthorized blocks and zero skipped, plus healthy HMI. Save the report, PCAP and notes. Trust the report, not the banner.

**RD-18:** In these images, Execute may report a red failure/BLOCKED when rejecting an unauthorized action, and it will not advance automatically. That label is not a packet verdict. Run the documented real protocol retest, inspect unchanged healthy device/HMI state and firewall evidence, record the result, then Mark Complete. A refused/timeout connection without state/evidence is not enough to claim DPI.
Execute can reject an action before any packet is sent; a failed expected-block
probe can also log BLOCKED even when the destination was reachable. Read details.

**RD-19:** PARTIAL may include successful attacks from earlier weak-policy training or smoke runs. Record current retest timestamps; compare those events with earlier weak-policy writes. Check for healthy restored state and blocked current attempts; do not clear audit or repeatedly reset/re-attack to make the banner green. Current successful unauthorized writes still fail.

## Quick help and remaining limitations

Follow Exercises **1.2 → 1.3 → 1.4 → 2.2 → 2.3 → 2.4**, then the bonus.
Use Feeder HMI for operations, Network Map for hosts/terminals, Workshop Status
for services. containd credentials are `containd` / `containd`; vendor/RTAC
SSH or RDP is `rangerdanger` / `rangerdanger`; OpenPLC is `openplc` / `openplc`.
These are public lab credentials, not production secrets.

The rc checkout fixes embedded containd routing (RD-04) and vendor desktop
startup (RD-09). If they still fail after the targeted update, stop for
instructor diagnosis; direct http://localhost:9080 remains a firewall access
path. Do not apply the old manual symlink workaround instead of installing
the rc checkout.

Save PCAPs from `/home/abc/pcaps/` in the engineering desktop before resetting;
generated reports use timestamped filenames, manual validation uses
`validation.pcap`. Allow roughly 2–3 seconds for physics/HMI updates.

Unchanged image limitations: exercise-header Reset Lab restores weak policy
and devices and deletes captures, while keeping notes/checkmarks; HMI Reset
lab resets the load model only (RD-20). Reset Progress separately clears
exercise notes/checkmarks/log, not running devices or the shared plan.
Reload may open step 1 without losing saved work; select the previous step
in the navigator (RD-21). OpenPLC Programs timeout is not fixed or diagnosed
by this release (RD-22); use HMI/RTAC evidence, not PLC restarts.

**Not covered by automated tests:** frozen-image report and protocol
retests, real browser login/desktop input and saved downloads, plus fresh
vendor mount/startup on macOS and Windows (NTFS and WSL ext4). Static content
tests are not runtime enforcement or GUI proof.
