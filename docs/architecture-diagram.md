# Docker architecture

How the platform and selected range package are composed: services, image
modes, Docker networks and browser request paths. For the teaching topology
and RTAC routing see [`architecture.md`](architecture.md); for code layout
see [`CONTRIBUTING.md`](../CONTRIBUTING.md).

All six Mermaid regions (including the README overview) are generated by
[`scripts/generate_architecture.py`](../scripts/generate_architecture.py).
Run `python3 scripts/generate_architecture.py` after changing the inputs;
CI runs `python3 scripts/generate_architecture.py --check` and rejects drift.
The generator reads package-declared topology pointers, manifests, source and
release Compose files, platform/package nginx routes, the frontend version
and the release image inventory. It does not run Docker or contact registries.
Non-declarative logical edges live in the small reviewed
[`architecture/overlay.yml`](architecture/overlay.yml), with repository source
citations. A checker verifies citation paths exist, not that their semantics
remain correct; those edges still require code review.

## Compose stack - services, images, dependencies

Each package runs beside the persistent **platform** (`rangerdanger-platform`:
backend, frontend, proxy). The selected **range** is project `rangerdanger`;
US and EU are alternatives, not simultaneous projects. Root Compose files
own the platform; each package owns `compose.source.yml` and
`compose.release.yml`.

Boxes show **source** build/pull declarations separately from **release**
pulls. A service can declare both `build:` and `image:`: the latter names
the build output in source mode. In particular, source mode builds
`rangerdanger-firewall` from the containd git ref in its context (or the
explicit `CONTAIND_SOURCE` override); release mode pulls containd `latest`.
The diagrams describe image preparation, not a promise that the backend
builds images: lifecycle startup uses prebuilt images.

Dependency arrows point from dependent to prerequisite, and carry the exact
Compose condition. Solid = `service_started`; dashed = `service_healthy`
(or another explicitly named completion condition). These are startup
relationships, **not logical traffic flows**. Namespace links mean one
network namespace, not an additional NIC. The separately cited lifecycle
edge describes backend-managed startup, routes and default policy; there
is no cross-project Compose `depends_on`.

## Docker network wiring

Each service appears once. Single-homed services sit inside their network;
multi-homed services sit outside, with one attachment edge per NIC labelled
`IP · iface` (interface names are shown where Compose pins them). Small circles
are network attachment points, not containers. FUXA's label notes its shared
poller namespace; there is no independent poller NIC. Colours are authored
presentation metadata; addresses and memberships remain generated from Compose.

at `/containd/`. **Exception:** the firewall also publishes loopback-only
direct ports for instructor/debug use. Those ports are not the reserved
management path and do not promise management reachability under every
policy. The backend reaches containd on `mgmt_net`.

Terminal selection is restricted to services mapped to topology nodes in
the active package's manifest: solver and sidecar services are not terminal
targets. WebSocket terminal requests pass through the API to Docker exec.
Cross-zone teaching traffic uses the firewall; dependency/identity arrows
in earlier diagrams do not imply protocol traffic.

**Published host ports are loopback-only:** `127.0.0.1:8088` maps to proxy
8080; firewall `127.0.0.1:9080`, `:9443`, `:2222` map to container 8080,
8443 and 2222. There are no other published host ports. The backend
publishes no host port; its Docker network is not "loopback-bound".
See [`SECURITY.md`](../SECURITY.md) before considering external access.

**Critical bind mounts:**

- Backend loads `./lab-definitions:/lab-definitions:ro`; restart it after
  content changes. `${RANGERDANGER_ROOT}:${RANGERDANGER_ROOT}:ro` preserves
  absolute host paths for Compose bind mounts accepted by the Docker daemon.
- Backend mounts `/var/run/docker.sock` for orchestration. Access to the
  unauthenticated backend/terminals is a host-level trust boundary, not a
  sandbox for untrusted users.
- `./data/proxy-routes` is writable at backend `/proxy-routes` and read-only
  at proxy `/etc/nginx/rd-routes`. Lifecycle startup installs the package's
  `nginx.routes.conf`, tests nginx, then reloads; a failed reload restores
  the prior file.
- Firewall state maps to `/data`: US uses `data/firewall`, EU uses
  `data/eu-iec104-substation/firewall`. Workshop reset clears captures and
  removes `users.db`/`sessions.db` as a credential-recovery backstop;
  the firewall must restart to reseed credentials. Preserve pre-upgrade
  backups: see [upgrade guidance](quickstart.md#upgrading-to-v020).
- US OpenPLC mounts `data/openplc` at `/workdir` for a local program
  override. EU OpenPLC has no corresponding host state bind.
- `./proxy/nginx.conf:/etc/nginx/nginx.conf:ro` supplies platform routes
  plus the package route include. Range routes install during a range
  start (`POST /api/range`), not merely by editing the source file.
